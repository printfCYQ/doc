# 操作系统

操作系统（Operating System，简称 OS）就是你电脑里那个"大管家"。你写的程序不能直接去碰硬盘、内存、网卡这些硬件——那样太乱也太危险。OS 站在硬件和你（的程序）之间，统一帮你管资源、调度任务、隔离保护。

打个比方：你是老板（程序），OS 是行政+人事+后勤总管。你想用会议室（CPU）、调档案（文件）、发快递（网络），都得跟总管说，它帮你安排，避免你和新来的实习生抢同一间会议室打起来。

这篇把面试和实战里最常碰到的几块讲透：**进程线程、调度、进程间通信、同步互斥、死锁、内存管理、文件系统、IO**。不堆公式，先把"为什么"讲清楚。

---

## 一、进程与线程

### 进程是什么

进程（Process）是**一个正在运行的程序实例**。你双击一个 exe，或者跑 `node app.js`，操作系统就给它建一个进程。

每个进程有自己的地盘：
- **独立的虚拟地址空间**（它以为自己独占整块内存，其实是 OS 骗它的）
- **代码段、数据段、堆、栈**
- **PCB（Process Control Block，进程控制块）**：OS 给每个进程建的小档案，记着它的 ID、状态、寄存器、打开的文件等。调度全靠它。

### 线程是什么

线程（Thread）是**进程里的一条执行流**。一个进程可以开多个线程，它们**共享**进程的地址空间（内存、文件），但各自有独立的栈和寄存器。

进程和线程的关系，像"公司"和"员工"：
- 公司（进程）有独立的办公楼、账户、公章（资源）
- 员工（线程）共享这些资源，但每个人手头自己的记事本（栈）是分开的
- 开除一个员工（线程崩）可能拖垮整个公司；公司倒闭（进程退出）所有员工都失业

### 进程 vs 线程 vs 协程

| 维度 | 进程 | 线程 | 协程（Coroutine） |
|------|------|------|------|
| 地址空间 | 独立 | 共享进程 | 共享线程 |
| 切换开销 | 大（要换页表） | 中（换栈和寄存器） | 极小（用户态自己切） |
| 由谁调度 | 操作系统内核 | 操作系统内核 | 程序自己（用户态） |
| 崩溃影响 | 只影响自己 | 可能拖垮进程 | 只影响自己 |

**协程**不是 OS 概念，是语言层面的（Go 的 goroutine、Python 的 asyncio、Java 的虚拟线程思路）。它在线程里再细分，切换不进内核，所以轻量。一个线程能跑上万个协程。

## 二、进程的状态与切换

进程一辈子在几个状态之间跳：

```
        创建
         ↓
    [就绪] ←→ [运行]
      ↑        |
      |        ↓ (等 IO/锁)
    [阻塞]  ←──┘
         ↓
        终止
```

- **就绪（Ready）**：一切就绪，就等 CPU 了
- **运行（Running）**：正在 CPU 上跑
- **阻塞（Blocked/Waiting）**：在等某件事（读磁盘、等锁），这时候即使给 CPU 也没用

**上下文切换（Context Switch）**：OS 把当前进程的运行现场（寄存器、程序计数器）存到 PCB，再加载下一个进程的现场。这一步有开销——要刷 TLB、换页表，所以"线程多了不一定快"，切换太频繁反而慢。

## 三、进程调度算法

CPU 是稀缺资源，多个就绪进程抢，OS 得排个队。常见算法：

### 先来先服务（FCFS）
谁先到谁先跑，跑完才轮下一个。简单公平，但**长作业卡在前面会让后面一堆短作业干等**（ convoy effect，护航效应）。

### 短作业优先（SJF）
优先跑预计时间短的。平均等待时间最短，但**长作业可能饿死**，而且 OS 其实很难预知一个任务要跑多久。

### 时间片轮转（RR）
每个进程给一小段时间（时间片，比如 10ms），时间一到就强行切到下一个，循环。兼顾公平和响应速度。**时间片太大**就退化成 FCFS，**太小**切换开销占比太高。

### 优先级调度
给进程分优先级，高优先级先跑。要小心**低优先级饿死**，解决办法是**老化（Aging）**——等得越久优先级自动涨。

### 多级反馈队列（MLFQ）
实际系统（如 Unix 系）常用。多个队列、优先级不同、时间片不同；新进程进最高优先级的队列，用完时间片没结束就降级。既照顾交互型（短、频繁），又不亏待计算型（长、老实）。

## 四、进程间通信（IPC）

进程默认**内存隔离**，不能直接读对方变量。要通信得走 OS 提供的"官方渠道"：

| 方式 | 说明 | 场景 |
|------|------|------|
| 管道（Pipe） | 一根单向数据流，父进程 fork 子进程常用 | `ls \| grep` 那种 |
| 命名管道（FIFO） | 有名字的管道，无亲缘关系也能用 | 两个独立进程 |
| 消息队列 | OS 维护的带类型的消息链表 | 不想自己管缓冲时 |
| 共享内存 | 把同一块物理内存映射到多个进程地址空间，**最快** | 大数据量（如数据库、GPU） |
| 信号量（Semaphore） | 不是传数据，是**同步/互斥**的计数器 | 配合共享内存防冲突 |
| 信号（Signal） | 异步通知，如 `Ctrl+C` 发 SIGINT | 通知类，不传大量数据 |
| Socket | 不仅能本机，还能跨网络 | 网络服务、本地进程也常用 |

**最快的是共享内存**（少了内核拷贝），但要自己用信号量管同步，否则会"写一半被读"。

## 五、同步与互斥

多进程/多线程同时改一份共享数据，会出乱子。经典例子：两个线程同时给 `count++`。

`count++` 在 CPU 眼里不是一步，而是三步：**读内存 → 加 1 → 写回**。两个线程交错执行，最终结果可能比预期少。

### 临界区
**一段同时只能有一个线程进去执行的代码**（比如改共享变量的那段）。保护临界区的机制就是"锁"。

### 互斥锁（Mutex）
最常用。谁拿到锁谁进临界区，别人得等。等的时候线程**睡眠**（让出 CPU），适合临界区耗时长的。

### 自旋锁（Spinlock）
等锁的时候**不睡，原地空转**（while 抢锁）。省了睡眠/唤醒的开销，但占着 CPU。适合临界区极短、多核场景（内核里常见）。

### 读写锁（RWLock）
读多写少场景优化：多个读可以同时进行，写的时候独占。

### 条件变量（Condition Variable）
配合互斥锁用，用来"等某个条件成立"。典型：**生产者-消费者模型**——队列空时消费者等（`wait`），生产者放入后 `signal` 唤醒。

### 信号量
一个整数计数器，P 操作减一（不够就等），V 操作加一（唤醒等待者）。既能做互斥（初值 1），也能做同步（初值 0 控制顺序）。

```java
// 生产者-消费者（用 Java 的 BlockingQueue，底层就是锁+条件变量）
import java.util.concurrent.*;

BlockingQueue<Integer> q = new ArrayBlockingQueue<>(10);

// 生产者
new Thread(() -> {
    try { for (int i = 0; i < 100; i++) q.put(i); }   // 满了自动阻塞
    catch (InterruptedException e) {}
}).start();

// 消费者
new Thread(() -> {
    try { while (true) System.out.println(q.take()); } // 空了自动阻塞
    catch (InterruptedException e) {}
}).start();
```

## 六、死锁

**死锁**：两个或以上进程互相拿着对方想要的锁，谁都不放，全卡死。

### 四个必要条件（同时满足才死锁）
1. **互斥**：资源只能一个人用
2. **占有并等待**：拿着一个还等另一个
3. **不可抢占**：别人不能强抢你的资源
4. **循环等待**：A 等 B、B 等 A，成环

只要**破坏任意一个**就能防死锁。

### 怎么防
- 破坏"占有并等待"：一次性申请所有资源
- 破坏"不可抢占"：申请不到就释放已持有的
- 破坏"循环等待"：**给资源编号，只能按编号从小到大申请**（最常用，简单）

### 银行家算法（避免死锁）
不是预防，而是"每次分配前算一下，分配后系统是否还能让所有人跑完"。能跑就分，不能就拒。名字来自"银行放贷不能让系统破产"。偏理论，实际系统很少真跑，但面试常考。

### 检测 + 解除
允许死锁发生，但定期检测（找资源分配图里的环），发现了就**杀掉一个进程**或**回滚**来解除。

## 七、内存管理（重点）

程序以为自己用的是一整块从 0 开始的连续内存，其实背后全是 OS 在"变魔术"。

### 为什么需要虚拟内存
- **隔离**：A 进程崩了不能改写 B 的内存
- **扩展**：物理内存不够时，用磁盘（ swap）顶上
- **方便**：程序不用管自己被加载到物理内存哪

### 地址转换：分页
内存被切成固定大小的**页（Page，通常 4KB）**。程序的虚拟地址通过**页表**翻译成物理地址。

```
虚拟地址 → [页号 | 页内偏移] → 查页表 → 物理页框 + 偏移 → 物理地址
```

- **页表**存在内存里，每个进程一份
- **TLB（快表）**：页表查询太慢，CPU 加了个小缓存，存最近用过的页表项。TLB 命中就快，没命中（TLB miss）要去内存查页表

### 分段
按"逻辑意义"分段：代码段、数据段、堆、栈。段长不固定。现代系统大多**段页式结合**：先分段，段内再分页。

### 虚拟内存 + 缺页中断
程序用的总内存可以超过物理内存。暂时不用的页被换到磁盘（swap）。访问一个不在内存的页，触发**缺页中断（Page Fault）**，OS 把它从磁盘读回来。

### 页面置换算法（内存满了换谁出去）
- **OPT（最佳）**：换"未来最久不用"的。理论最优，但 OS 没法预知未来，所以只是衡量标准
- **FIFO**：先进先出。简单，但可能换掉常用页（Belady 异常：给更多内存反而缺页更多）
- **LRU（最近最少用）**：换最久没访问的。最贴近实际，性能好。实现靠"访问时间戳"或近似链表

### 碎片
- **外部碎片**：内存被切成很多不连续小洞，总够但凑不出一块大的。分页能缓解
- **内部碎片**：分配的页没用完，页内空着浪费。比如要 3.5KB 也占一整 4KB 页

## 八、文件系统

文件是"一堆带名字的字节"。OS 用**树状目录**组织。

### inode
类 Unix 系统里，文件元数据（权限、大小、创建时间、数据块指针）存在 **inode** 里，**文件名只是目录项指向 inode 的链接**。所以：
- 硬链接 = 多个文件名指向同一 inode（删一个另一个还在）
- 软链接（符号链接）= 一个文件存的是"另一个文件的路径"（像快捷方式，原文件删了它就失效）

### 文件怎么存到磁盘
大文件的数据块可能散落在磁盘各处，inode 里用**直接指针 + 间接指针**串起来（直接指向数据块，或指向"装了一堆指针的块"）。

### IO 栈（简化）
```
应用程序
  → 系统调用 (read/write)
  → 文件系统层（管 inode、目录）
  → 通用块层（把请求合并、排序，减少磁头移动）
  → 设备驱动
  → 磁盘/SSD
```
中间有**页缓存（Page Cache）**：读过的磁盘内容缓存在内存，下次直接命中，这就是为什么第二次读文件快得多。

## 九、设备管理与 IO

- **中断（Interrupt）**：硬件干完活了，发个信号打断 CPU，CPU 停下当前活去处理（比如网卡收到包）。没有中断，CPU 就只能不停轮询，浪费。
- **DMA（直接内存访问）**：让磁盘/网卡**自己**把数据搬进内存，不用 CPU 一个个字节拷贝。搬完发中断通知。解放了 CPU。
- **IO 控制方式演进**：轮询 → 中断驱动 → DMA → 通道（专用处理器）

## 十、用户态与内核态

CPU 有两种权限级别：
- **用户态**：你写的普通程序跑在这，不能直接碰硬件、不能执行特权指令
- **内核态**：OS 内核跑在这，啥都能干

程序想读文件、建进程，得通过**系统调用（syscall）**"陷"进内核态，内核帮你干完再回来。这中间的切换（陷阱/上下文切换）有开销，所以**频繁 syscall 是性能杀手**（比如一行行 read 小文件，不如一次读一大块）。

## 十一、新手最常踩的坑

1. **以为多线程一定快**：线程创建/切换有成本，任务太小反而被 overhead 拖慢；IO 密集型才适合多线程/协程。
2. **共享变量不加锁**：`i++` 不是原子的，并发改会丢更新。用原子类或锁。
3. **死锁：拿锁顺序不一致**：线程 A 先锁 1 再锁 2，线程 B 先锁 2 再锁 1，就成环。统一加锁顺序即可破。
4. **死等而非超时**：`lock()` 一直等，不如 `tryLock(timeout)`，拿不到就走别的路，避免永久卡。
5. **混淆进程和线程的内存模型**：线程共享堆、不共享栈；进程默认全隔离。
6. **觉得内存够用就不会 OOM**：可能是虚拟内存地址空间用尽（32 位程序上限 4GB），或文件描述符耗尽。
7. **TLB/缓存当不存在**：频繁随机访问大数组比顺序访问慢得多，因为缓存命中率低。

## 十二、练习

1. 用你熟悉的语言写一个"两个线程交替打印 1-100"的程序，体会锁和条件变量。
2. 画一个"进程状态转换图"，标出哪些转换会触发上下文切换。
3. 虚拟地址 0x00005F20，页大小 4KB，页号是多少？页内偏移是多少？（提示：4KB = 2^12）
4. 银行家算法里，如果"一次性分配所有资源"能防死锁，它破坏的是四个必要条件里的哪一个？
5. 解释为什么"第二次读同一个大文件明显更快"，并指出是哪一层缓存在起作用。

## 十三、速查口诀

- 进程管资源、线程管执行，协程轻量用户态
- 进程隔离、线程共享，崩一个线程可能带崩进程
- 调度：FCFS 公平但护航，RR 轮转靠时间片，优先级小心饿死
- 通信最快是共享内存，但要自己加锁同步
- 临界区：同时只能一个进
- 死锁四条件，破一个就行；编号申请资源最省事
- 分页用页表、TLB 是缓存；LRU 换最久没用的页
- 文件靠 inode，硬链同 inode，软链是路径
- 用户态不能碰硬件，要干脏活走系统调用
