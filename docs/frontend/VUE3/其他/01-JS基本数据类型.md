## 01-JS基本数据类型

> 在 JavaScript 中，基本数据类型包括以下几种：
> 
> 1.  **Number（数字）**：用于表示整数或浮点数。例如：123、3.14159。
> 2.  **String（字符串）**：用于表示文本数据。例如："Hello, World!"。
> 3.  **Boolean（布尔值）**：只有两个值：true（真）或 false（假）。
> 4.  **Null（空值）**：表示一个空值或无效的值。
> 5.  **Undefined（未定义）**：表示一个变量尚未被赋值。
> 6.  **Symbol（符号）**：一种特殊的数据类型，用于创建唯一的标识符。
> 7.  **BigIn****t（大整数）**：可以处理超出普通整数范围的大数值，例如存储非常大的数字或处理高精度的计算。它可以避免整数溢出等问题。



> **JS原始和引用类型的区别**
> 
> 在JavaScript中，数据类型主要分为两种：原始类型（Primitive Types）和引用类型（Reference Types）。它们之间的主要区别在于数据的存储方式和操作方式。
> 
> **原始类型（Primitive Types）**
> 
> 原始类型包括以下几种：
> 
> 1.  **Number**：表示数值，如42或者3.14159。
> 2.  **String**：表示文本数据，用单引号（'）或双引号（"）括起来。
> 3.  **Boolean**：表示逻辑值，有两个取值：true 和 false。
> 4.  **Null**：表示一个空值或者“无”。只有一个值：null。
> 5.  **Undefined**：表示变量未定义。只有一个值：undefined。
> 6.  **Symbol**（ES6新增）：表示唯一的值。
> 
> 原始类型的值直接存储在变量位置的内存中，也就是说，当你将一个原始类型的值赋给变量时，实际上是在内存中为这个值开辟了一个新的空间。因此，当你修改一个原始类型的值时，实际上是创建了一个新的原始值。
> 
> **引用类型（Reference Types）**
> 
> 引用类型在JavaScript中主要是指对象（Object），包括数组（Array）、函数（Function）、日期（Date）等。
> 
> 引用类型的值不直接存储在变量中，而是存储在内存中的某个位置，变量中保存的实际上是一个指向该位置的指针。也就是说，变量中存储的是对象的内存地址，而不是实际的对象。因此，当你修改一个引用类型的值时，实际上是在修改内存中的对象，而不是创建新的对象。
> 
> 由于引用类型存储的是内存地址，因此当两个变量引用同一个对象时，它们实际上指向的是同一个内存地址。因此，修改其中一个变量的属性，另一个变量的属性也会发生改变。
> 
> 总的来说，原始类型和引用类型的主要区别在于数据的存储方式和操作方式。原始类型的值直接存储在变量中，而引用类型的值则存储在内存中，变量中存储的是指向该值的指针。

## 02-This指向

> **this 永远指向最后调用它的那个对象。【不知道】**
> 在 JavaScript 中，`this`的指向是一个比较复杂的问题，它会根据不同的情况指向不同的对象。以下是`this`常见的几种指向情况：
> 
>   
> 
> -   对象调用：`this`指向该对象。例如，在对象`obj`中调用函数`func`，那么`this`就指向`obj`。
> -   直接调用的函数：`this`指向全局`window`对象。例如，在全局作用域中直接调用函数`func`，那么`this`就指向`window`。
> -   通过`new`的方式调用：`this`永远被绑定在新创建的对象上。例如，通过`new`创建一个对象实例，并在其中调用函数`func`，那么`this`就指向这个新创建的对象实例。
> 
>   
> 
> 除此之外，箭头函数中的`this`指向的是箭头函数所在作用域的上一级作用域中的`this`，定时任务中的`this`指向`window`，`call`、`apply`和`bind`等方法也可以改变`this`的指向。

## 03-本地缓存

> 在前端开发中，浏览器本地缓存方案有以下几种：
> 
>   
> 
> -   HTTP缓存：是一种保存资源副本并在下次请求时直接使用该副本的技术。当浏览器发现请求资源已经被存储，它会拦截请求，返回资源副本，而不会去服务器重新请求资源。
> -   Web SQL：是较新的Chrome浏览器支持，并以独立规范形式出现，引入了一组使用SQL操作客户端数据库的APIs。它的主要特点是能够在客户端存储大量结构化数据，并使用索引进行高性能检索。
> -   IndexDB：是为了能够在客户端存储客观数量的结构化数据，并且在这些数据上使用索引进行高性能的检索。对于少量数据，DOM存储非常友好，但不适合存储大量结构化数据，IndexDB就是为了解决这个问题而生的。
> -   Cookie：是存储在客户端的一小段文本，伴随着每次http请求发送到服务器。它通常用来存储用户信息、会话信息等。Cookie的大小限制为4KB，并且在某些情况下可能会被禁用。
> -   LocalStorage：是一种在浏览器中持久化存储数据的方案，它的数据在浏览器关闭后仍然存在。LocalStorage的容量一般为5MB，并且可以通过 JavaScript 进行读取和写入操作。
> -   SessionStorage：与LocalStorage类似，但是它的数据在浏览器关闭后会被清除。SessionStorage通常用于存储与当前会话相关的数据，例如登录信息、购物车信息等。
> 
>   
> 
> 这些缓存方案各有优缺点，在实际应用中需要根据具体需求选择合适的缓存方案。

## 04-Promise 优缺点

> Promise 是 JavaScript 中的一种异步处理机制，它有以下优点：
> 
>   
> 
> 1.  **简洁明了的异步编程**：Promise 提供了一种直观、简洁的方式来处理异步操作的结果，使得异步代码更易于理解和维护。
> 2.  **链式调用**：Promise 的链式调用使得异步操作可以依次进行，代码逻辑更加清晰，避免了回调地狱的问题。
> 3.  **错误处理**：Promise 提供了方便的错误处理机制，可以通过 `.catch()` 方法捕获和处理异步操作中的错误。
> 4.  **兼容性较好**：Promise 在现代浏览器中得到广泛支持，并且可以通过 polyfill 实现对旧版本浏览器的兼容。
> 
>   
> 
> 然而，Promise 也有一些缺点：
> 
>   
> 
> 1.  **无法取消**：一旦创建了 Promise，就无法取消或中断异步操作。
> 2.  **状态不可变**：Promise 的状态（fulfilled 或 rejected）是不可变的，一旦确定就无法改变。
> 3.  **嵌套结构复杂**：在复杂的异步操作中，可能会出现 Promise 的嵌套，增加了代码的复杂性。
> 
>   
> 
> 总体来说，Promise 是一种非常有用的工具，它改善了异步编程的体验，但在使用时需要注意一些潜在的问题。在实际开发中，根据具体的需求和场景，合理地使用 Promise 可以提高代码的可读性和可维护性😉

## 07-获取数据在哪个钩子函数

> 在 Vue 中，获取数据的生命周期阶段取决于你的数据是在组件挂载之前还是之后获取的。
> 
> ​  
> 
> 如果你需要在组件挂载之前获取数据，你可以在 \`beforeCreate\` 生命周期钩子函数中进行数据获取操作。在这个阶段，Vue 实例的 \`el\` 和 \`data\` 属性尚未初始化，因此你无法访问 DOM 或使用实例的数据。
> 
> ​  
> 
> 如果你需要在组件挂载之后获取数据，你可以在 \`created\` 生命周期钩子函数中进行数据获取操作。在这个阶段，Vue 实例的 \`data\` 属性已经初始化，但 \`el\` 属性仍然为 \`undefined\`，因此你仍然无法访问 DOM。
> 
> ​  
> 
> 如果你需要在组件挂载之后访问 DOM 并获取数据，你可以在 \`mounted\` 生命周期钩子函数中进行数据获取操作。在这个阶段，Vue 实例已经完全挂载，你可以访问 DOM 并使用实例的数据。
> 
> ​  
> 
> 请注意，在实际应用中，你应该尽量避免在 \`created\` 或 \`mounted\` 钩子函数中进行大量的数据获取操作，因为这可能会导致页面加载速度变慢。如果可能的话，你应该尝试在服务器端预先获取数据，并在组件挂载时将数据传递给 Vue 实例，以提高应用的性能。

## 08-页面和组件的生命周期执行顺序

> 页面---beforeCreate  
> 页面---created  
> 页面---beforeMount  
> 组件---beforeCreate  
> 组件---created  
> 组件---beforeMount  
> 组件---mounted  
> 页面---mounted
> 在 Vue 中，父组件和子组件的生命周期执行顺序如下：
> 
>   
> 
> 1.  创建阶段：
> 
> -   父组件：`beforeCreate`\>`created`\>`beforeMount`
> -   子组件：`beforeCreate`\>`created`\>`beforeMount`\>`mounted`
> -   父组件：`mounted`
> 
> 2.  更新阶段：
> 
> -   父组件：`beforeUpdate`
> -   子组件：`beforeUpdate`\>`update`
> -   父组件：`update`
> 
> 3.  销毁阶段：
> 
> -   父组件：`beforeDestroy`
> -   子组件：`beforeDestroy`\>`destroyed`
> -   父组件：`destroyed`
> 
>   
> 
> 需要注意的是，如果页面中使用了`vue`内置的组件`keep-alive`，会多两个生命周期：`activated`和`deactivated`。

> ## HTTP 与 HTTPS 区别
> 
> -   加密： HTTPS 是 HTTP 协议的更加安全的版本，通过使用SSL/TLS进行加密传输的数据；
> -   连接方式： HTTP（三次握手）和 HTTPS （三次握手+数字证书）连接方式不一样；
> -   端口： HTTP 默认的端口是 80和 HTTPS 默认端口是 443
> ## HTTP2 是什么？
> 
> HTTP/2 超文本传输协议第2版，是 HTTP/1.x 的扩展。所以 HTTP/2没有改动HTTP的应用语义，仍然使用HTTP的请求方法、状态码和头字段等规则。
> 
> 它主要修改了HTTP的报文传输格式，通过引入二进制分帧层实现性能的提升。
> 
> 现有很多主流浏览器的 HTTPS/2 的实现都是基于SSL/TLS的，所以基于 SSL/TLS 的 HTTP/2 连接建立过程和 HTTPS 差不多。在建立连接过程中会携带标识期望使用 HTTP/2 协议，服务端同样方式回应。

    for (var j = 0; j < len - 1 - i; j++) {

function getType(target) {
    return Object.prototype.toString.call(target).slice(8, -1);
}
function deepClone(target) {
    // 处理 原始值 null、undefined、number、string、symbol、bigInt、boolean
    if (typeof target !== "object" || target === null) {
        return target;
    }
    // 处理 array
    if (Array.isArray(target)) {
        return target.map((e) => deepClone(e));
    }
    // 处理 function
    if (getType(target) === "Function") {
        return eval(`(${target.toString()})`).bind(this); 
        // function 声明需要用"("、")"包裹
    }
    // 拷贝日期
    if (getType(target) === "Date") {
        return new Date(target.valueOf());
    }
    // 拷贝正则
    if (getType(target) === "RegExp") {
        return new RegExp(target);
    }
    // 处理 map
    if (getType(target) === "Map") {
        let map = new Map();
        target.forEach((v, k) => {
            map.set(k, deepClone(v));
        });
        return map;
    }
    // 处理 set
    if (getType(target) === "Set") {
        let set = new Set();
        for (let val of target.values()) {
            set.add(deepClone(val));
        }
        return set;
    }
    // 处理 object
    if (getType(target) === "Object") {
        let cloneTarget = {};
        for (let key in target) {
            cloneTarget[key] = deepClone(target[key]);
        }
        return cloneTarget;
    }
    return target;
}

## 出了一道题 (口述答案，闭包)

> 闭包是 JavaScript 中的一个重要概念。简单来说，闭包是指函数和其相关的上下文（包括变量、函数等）的组合。
> 
> 闭包的特点是能够保留函数内部的状态，并在函数外部访问和操作这些状态。以下是一个简单的闭包示例：
> 
> function createCounter() {  
> let count = 0;  
>   
> function increment() {  
> count++;  
> console.log(count);  
> }  
>   
> return increment;  
> }  
>   
> let counter = createCounter();  
> counter();  
> counter();
> 
>   
> 
> 在这个示例中，`createCounter`函数返回了一个内部函数`increment`。`increment`函数能够访问`createCounter`函数中的变量`count`，即使在`createCounter`函数执行完毕后，`count`的值仍然被保留在闭包中。
> 
> 通过返回内部函数并在外部调用，我们可以在不同的上下文环境中访问和修改闭包中的变量。这就是闭包的作用。
> 
> 闭包在 JavaScript 中有很多实际的应用，例如：
> 
> -   **私有变量和方法**：通过闭包可以创建私有变量和方法，限制对其的访问和修改。
> -   **缓存和记忆化**：利用闭包可以缓存计算结果，避免重复计算。
> -   **模块化和封装**：使用闭包可以将相关的功能和状态封装在一起，形成模块。
> 
> 理解闭包对于编写高效和可维护的 JavaScript 代码非常重要。它允许我们在函数内部创建独立的作用域，更好地管理和控制变量的可见性和生命周期。

> [https://juejin.cn/post/7260748045309837349?searchId=20240312120747EA0A4382FEA60D2BBFCD](https://juejin.cn/post/7260748045309837349?searchId=20240312120747EA0A4382FEA60D2BBFCD)
> ## 区别
> 
> -   源码组织方式变化：使用 TS 重写
> -   支持 Composition API：基于函数的API，更加灵活组织组件逻辑（vue2用的是options api）
> -   响应式系统提升：Vue3中响应式数据原理改成proxy，可监听动态新增删除属性，以及数组变化
> -   编译优化：vue2通过标记静态根节点优化diff，Vue3 标记和提升所有静态根节点，diff的时候只需要对比动态节点内容
> -   打包体积优化：移除了一些不常用的api（inline-template、filter）
> -   生命周期的变化：使用setup代替了之前的beforeCreate和created
> -   Vue3 的 template 模板支持多个根标签
> -   Vuex状态管理：创建实例的方式改变,Vue2为new Store , Vue3为createStore
> -   Route 获取页面实例与路由信息：vue2通过this获取router实例，vue3通过使用 getCurrentInstance/ userRoute和userRouter方法获取当前组件实例
> -   Props 的使用变化：vue2 通过 this 获取 props 里面的内容，vue3 直接通过 props
> -   父子组件传值：vue3 在向父组件传回数据时，如使用的自定义名称，如 backData，则需要在 emits 中定义一下
> ### Object.defineProperty只能劫持已经存在的属性（vue2为了解决这 单独写了一些API $set、$delete......）
> 
> `$set`方法是 Vue.js 框架提供的一个用于更新 Vue 实例中响应式数据的方法。它的作用是在 Vue.js 实例创建后给一个对象添加一个属性，并确保这个新属性是响应式的。当新属性的值发生变化时，Vue.js 可以检测到这个变化并及时更新视图。
> 
> `$set`方法的语法如下：Vue.set(object, propertyName, value)
> 
> 其中：
> 
> -   `object`：要添加属性的对象；
> -   `propertyName`：新属性的名称；
> -   `value`：新属性的值。
> 
> `$set`方法可以作为 Vue 实例的方法直接调用，也可以通过全局的`Vue.set`来调用。在组件内部，通常使用`this.$set`。对于数组，调用方式为`this.$set(array, index, newValue)`；对于对象，调用方式为`this.$set(object, key, value)`。

## vue2 vue3 diff 的区别

> 在Vue 2和Vue 3中，虚拟DOM的diff算法有一些区别，主要体现在Vue 3中对diff算法的优化和改进。下面是Vue 2和Vue 3中diff算法的一些主要区别：
> 
> ### Vue 2中的diff算法：
> 
> -   Vue 2使用的是双端比较算法（Double Virtual DOM），即将新旧虚拟DOM树分别从头部和尾部开始进行比较，以尽可能减少操作的次数。
> -   Vue 2中的diff算法是逐级比较，即从父节点到子节点逐层比较，当遇到不同的节点时，会递归比较其子节点。
> -   Vue 2中的diff算法在处理大型列表或复杂视图时可能会存在性能问题，因为它需要逐级比较所有节点。
> 
> ### Vue 3中的diff算法：
> 
> -   Vue 3采用了更高效的静态树提升（Static Tree Hoisting）技术，通过对模板进行静态分析，将静态节点提升为常量，减少对动态节点的比较。
> -   Vue 3引入了缓存策略，即在对比过程中会使用缓存来加速对比，避免重复计算。
> -   Vue 3中的diff算法在处理大型列表或复杂视图时性能更优，因为它减少了不必要的比较操作，提高了渲染效率。
> 
> 总的来说，Vue 3对diff算法进行了优化和改进，引入了静态树提升和缓存策略等技术，提高了大型列表和复杂视图的渲染效率。这些改进使得Vue 3在性能方面有了明显的提升，特别是在处理大型应用或数据量较大的场景下。

## LocalStorage和sessionStorage的区别

> LocalStorage 和 sessionStorage 都是 Web 存储的一种方式，用于在浏览器中存储数据。它们的主要区别在于：
> 
> -   **存储时长**：LocalStorage 存储的数据在浏览器关闭后仍然保留，而 sessionStorage 存储的数据在浏览器关闭或会话结束后会被清除。
> -   **作用域**：LocalStorage 的数据在同一浏览器的不同标签页或窗口中都可以访问，而 sessionStorage 的数据只能在当前标签页或窗口中访问。
> -   **存储大小**：LocalStorage 和 sessionStorage 的存储大小都有限制，通常为几兆字节，但具体的限制可能因浏览器而异。
> -   **应用场景**：由于 LocalStorage 的数据持久性，它适用于长期存储用户偏好、设置等数据；而 sessionStorage 则适用于存储与当前会话相关的数据，例如登录状态、购物车信息等

## dom事件委托，代理机制

> 在 JavaScript 中，页面中事件处理程序的数量与页面整体性能直接相关。每个函数都是对象，都占用内存空间，对象越多，性能越差。并且，为指定事件处理程序所需访问 DOM 的次数会先期造成整个页面交互的延迟。因此，使用事件委托技术能让你避免对特定的每个节点添加事件监听器。 事件委托利用事件冒泡，可以只使用一个事件处理程序来管理一种类型的事件。当事件触发时，把要做的事委托给父元素（或父元素的父元素）来处理。例如，\`click\` 事件冒泡到 \`document\`。这种操作称之为事件委托或事件代理。 事件委托的主要优势在于可以减少 \`dom\` 操作，提高性能并简化代码。同时，新添加的元素也能够自动继承事件，无需手动为每个元素添加事件处理程序。

## vue2要改数组

> 在Vue 2中，当您需要修改数组时，您可以使用Vue提供的数组变异方法（mutating methods）来确保响应性。这些方法包括push、pop、shift、unshift、splice、sort和reverse。这些方法会修改原始数组，并且会触发视图更新。
```javascript
new Vue({
  data() {
    return {
      items: ['item 1', 'item 2', 'item 3']
    };
  },
  methods: {
    addItem() {
      this.items.push('new item');
    },
    removeItem(index) {
      this.items.splice(index, 1);
    }
  }
});
```
> 在上面的示例中，addItem方法使用push方法向items数组中添加新项，removeItem方法使用splice方法从items数组中移除指定索引位置的项。这些操作会在视图中更新数组的显示。
> 
> 需要注意的是，在Vue 2中，如果您使用非数组变异方法（如直接使用索引修改数组元素），Vue将无法检测到数组的变化，从而无法触发视图更新。因此，建议始终使用Vue提供的数组变异方法来修改数组。

## vue3 ref reactive哪个好？应用场景有哪些

> 在Vue 3中，ref和reactive是两种不同的响应式引用，它们各有适用场景。
> 
> ### ref
> 
> -   ref用于包装原始值，如字符串、数字、布尔值等，以及创建对单个对象的响应式引用。
> -   ref返回的是一个具有.value属性的响应式对象，您需要通过.value来访问或修改其内部的值。
> -   可以在模板中直接使用，而不需要.value。
> -   适用于基本类型数据或单个复杂数据类型（如对象或数组），当你需要保持对其中单个值的响应式引用时。
```plain
import { ref } from 'vue';

const count = ref(0);
const user = ref({ name: 'Alice', age: 25 });
```
> ### reactive
> 
> -   reactive用于创建复杂类型数据的响应式引用，如对象或数组。
> -   reactive返回的是一个完整的响应式对象，直接访问对象的属性，无需.value。
> -   适用于需要创建一个响应式的复杂对象，如一个包含多个属性的对象或对象数组。
```plain
import { reactive } from 'vue';

const state = reactive({
  count: 0,
  user: { name: 'Bob', age: 30 }
});
```
> ### 选择何时使用ref或reactive
> 
> 选择使用ref还是reactive通常取决于您要管理的数据类型和个人偏好。以下是一些指导原则：
> 
> -   当您需要处理基本数据类型时，如string、number或boolean，应使用ref。
> -   当您需要处理对象或数组，并希望整个对象或数组是响应式的时，应使用reactive。
> -   当您在reactive对象内部需要保持对某些属性的独立响应式引用时，可以在对象内部使用ref。
> -   当您想要保留对原始对象的引用，但同时需要响应式特性时，使用reactive。
> -   ref在模板中更方便，因为它可以自动解包，而reactive适合用在JavaScript中，减少.value的使用。
> 
> 在实际应用中，ref和reactive可以混合使用，以适应特定场景的需求。选择哪一个取决于具体的使用场景和开发者的偏好。
