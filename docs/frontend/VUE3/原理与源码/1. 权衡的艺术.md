# 1\. 权衡的艺术

## 1.1 命令式和声明式

-   命令式：关注过程，JQuery
-   声明式：关注结果，Vue

## 1.2 性能与科维性的权衡

-   声明式代码的性能不优于命令式代码的性能
-   在保持可维护性的同时让性能损失最小化

## 1.3 虚拟DOM的性能到底如何

| innerHTML(模板) | 虚拟DOM | 原声Javascript |
| --- | --- | --- |
| 心智负担中等 | 心智负担小 | 心智负担大 |
|  | 可维护性强 | 可维护性差 |
| 性能差 | 性能不错 | 性能高 |

## 1.4 运行时和编译时

-   纯运行时：没有编译过程，
-   运行时+编译时：Vue.js 3
-   纯编译时：性能好，有损灵活, Svelte

> 1.  **编译时**
> 
> -   **模板编译**：将Vue 3单文件组件的模板语法，如插值、指令，转化为渲染函数，决定如何创建虚拟DOM。
> -   **静态提升**：识别并将模板中的静态节点提升到渲染函数外，避免重新渲染，提升性能。
> -   **Tree-Shaking**：分析组件依赖，只打包实际使用的代码，剔除未引用部分，减小应用体积。
> 
> 2.  **运行时**
> 
> -   **虚拟DOM渲染**：状态变化时创建新虚拟DOM树，通过“diff”算法对比新旧树，仅更新有变化的真实DOM节点。
> -   **响应式系统操作**：跟踪响应式数据变化，自动触发组件重新渲染。
> -   **组件实例化与生命周期管理**：负责组件实例化，按顺序调用`beforeMount`、`mounted`等生命周期钩子，方便开发者执行特定操作。
> -   **事件处理**：处理组件的事件绑定，触发事件时执行对应的处理函数，可能引发组件状态改变与重新渲染 。

## 2.3 框架要做到良好的Tree-Shaking

-   Tree-Shaking:消除那些永远不会执行的代码（排除dead code）。
-   实现Tree-Shaking的前提：模块必须是ESM(ES Module)。
-   如果一个函数的调用会产生副作用，那就不能将其移除。
-   副作用：当调用函数的时候会对外部产生影响，比如修改了全局变量。
-   注释： /\*#\_\_PURE\_\_\*/ 作用是告诉rollup.js,不会产生副作用，放心删除。

```javascript
export const isHTMLTag = /#*__PURE__*/ makeMap(HTML_TAGS)
```

## 3.2 初识渲染器

-   虚拟DOM -> 渲染器 -> 真实DOM
-   实现一个渲染器

```html
<script>
  // 虚拟DOM
  const vnode = {
    tag: "div",
    props: {
      onClick: () => alert("hello"),
    },
    children: "clcik me",
  };
  
  function renderer(vnode, container) {
    // 使用 vnode.tag 作为标签名创建 DOM 元素
    const el = document.createElement(vnode.tag);
    // 遍历 vnode.props，将属性、事件添加到 DOM 元素上
    for (const key in vnode.props) {
      if (/^on/.test(key)) {
        // 如果 key 是 以 on 开头，说明它是事件
        el.addEventListener(
          key.substr(2).toLowerCase(), // 事件名称 onClick ---> click
          vnode.props[key] // 事件处理函数
        );
      }
    }
    // 处理children
    if (typeof vnode.children === "string") {
      //  如果 children 是字符串，说明它是元素文本子节点
      el.appendChild(document.createTextNode(vnode.children));
    } else if (Array.isArray(vnode.children)) {
      // 递归地调用 renderer 函数渲染子节点，使用当前元素 el 作为挂载点
      vnode.children.forEach((child) => renderer(child, el));
    }
    // 将元素添加到挂载点下
    container.appendChild(el);
  }
  
  renderer(vnode, document.body); // body 作为挂载点
</script>
```

## 3.3 组件到本质

-   组件就是一组DOM元素的封装
-   函数定义组件

```javascript
const Mycomponent = function () {
  return {
    tag: 'div',
    props: {
      onClick: () => alert('hello')
    },
    children: 'click me'
  }
}

function renderer(vnode, container) {
  if (typeof vnode.taq === 'string') {
    mountElement(vnode, container) // 标签元素  
  } else if (typeof vnode.tag === 'function') {
    mountComponent(vnode, container) // 组件
  }
}

function mountElement(vnode, container) {
    // 使用 vnode.tag 作为标签名创建 DOM 元素
    const el = document.createElement(vnode.tag);
    // 遍历 vnode.props，将属性、事件添加到 DOM 元素上
    for (const key in vnode.props) {
      if (/^on/.test(key)) {
        // 如果 key 是 以 on 开头，说明它是事件
        el.addEventListener(
          key.substr(2).toLowerCase(), // 事件名称 onClick ---> click
          vnode.props[key] // 事件处理函数
        );
      }
    }
    // 处理children
    if (typeof vnode.children === "string") {
      //  如果 children 是字符串，说明它是元素文本子节点
      el.appendChild(document.createTextNode(vnode.children));
    } else if (Array.isArray(vnode.children)) {
      // 递归地调用 renderer 函数渲染子节点，使用当前元素 el 作为挂载点
      vnode.children.forEach((child) => renderer(child, el));
    }
    // 将元素添加到挂载点下
    container.appendChild(el);
}

function mountCompenent(vnode, container) {
  // 调用组件函数， 获取组件要渲染的内容（虚拟DOM）
  const subtree = vnode.tag
  // 递归地调用 renderer 渲染 subtree
  renderer(subtree, container)
}

```

## 3.4 模板的工作原理

-   编译器：将模板编译为渲染函数
-   vue.js页面渲染流程：渲染函数（产生要渲染的内容【虚拟DOM】）-> 渲染器（渲染函数产生的虚拟DOM渲染为真实DOM）

## 3.5 Vue.js是各个模块组成的有机整体

-   组件的实现依赖于【渲染器】，模板的编译依赖于【编译器】
